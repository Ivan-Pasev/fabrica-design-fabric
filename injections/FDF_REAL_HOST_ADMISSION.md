# FDF()::UAC-011 — Real host skill admission, preserve current project intelligence

Use within the actual existing project opened in Antigravity, Cursor, Codex or Gemini CLI, or in a cloud project only with user-visible manual source context. This prompt is lower-priority than the host's policies and does not authorize file modifications.

**STATUS()**: State workspace/repo identity, Git commit/dirtiness, current user task, existing root/nested/global policy surfaces and active agent orchestration. Where global instruction discovery is unavailable, report UNKNOWN rather than assuming absent. Do not copy policy prose or secrets to an external report.

**FDF()**: Read the pinned first-party `fdf-upstream-portfolio` or `fdf-universal-bootstrap` SKILL.md in the verified FDF source. If not available to the host, say SKILL_NOT_INSTALLED_OR_NOT_DISCOVERED and propose explicit owner-reviewed delivery without writing files. No third-party source bodies should be installed merely because the portfolio lists 30 repositories.

**HOST PROBE**: Ask the human operator to independently inspect native skill settings/list before and after invocation. Antigravity: Customizations → skills; Gemini CLI: `/skills list`, then observe the consent-based activation when invoked; Cursor: Rules UI for applied project rules, with separate evidence for actual skill loading; Codex: consult current AGENTS.md precedence and supported skill discovery. Cloud AI Studio and ChatGPT Projects use manually provided instructions/sources and do not inherit a local IDE's skills automatically.

**BOUNDED OUTPUT**: Using read-only ProjectDNA, choose just one first-party skill for the current task and propose one concrete architectural or design improvement. Identify why it fits, what exists, how to avoid conflict, exact affected files *if later authorized*, tests and rollback. Do not apply, commit or deploy.

**OWNER EVIDENCE**: Present a checkable matrix of host-native discovery, actual activation signal, effective instructions respected, before/after Git status, optional rollback, missing evidence and operator decision. Treat model self-report as a hypothesis and host UI/operator observation as necessary independent evidence. The model cannot self-approve or declare an installed skill functional.

Stop at `OWNER_HOST_EVIDENCE_PENDING` unless current owner supplies real witnessed proof. Do not invent screenshots, timestamps, hashes, human signoff or successful app tests.
