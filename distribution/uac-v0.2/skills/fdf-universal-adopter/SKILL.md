# FDF() — Universal first-party adoption

Call `FDF()` as a read-only instruction in the active host. First inspect the host's **current project root, existing agent/global/nested rules, current owner objective and any protected scopes**; if any are inaccessible, state UNKNOWN. `FDF()` itself is not a privileged command in ChatGPT or AI Studio and it cannot authorize a tool action.

When the `tools/fdf.py` utility from this source bundle is already available in an approved external checkout, use read-only `FDF --project` to generate ProjectDNA, kernel mode and fit-ranked skill plan. A static signal is not semantic proof. Review the plan, collision report, and exact SHA with the owner; require separately authenticated host permissions before `apply --approve-plan`. Root AGENTS/GEMINI hooks are opt-in and require a different approved plan; never replace root project intelligence. Do not use legacy Antigravity workflows. Use progressive on-demand skills for Codex/Antigravity and the Gemini CLI, agent-requested Cursor rules, and manual context assets for ChatGPT Project/AI Studio.

After installation, `verify` confirms hashes (not IDE loading); read and obey project-local `.fabrica/KERNEL.md`, `SKILL_LATTICE.json`, `EVOLUTION_POLICY.md` and `STATE_AND_HANDOFF.md`. Guided evolution cycle: source observation → one bounded ProposalDNA → human accept/revise/reject → fresh authorization → measured tests → rollback/evidence → versioned handoff. Unapproved self-modification, auto-install, pushes, merge, publish, deploy and claim promotion are prohibited. Externally authored skills remain license-pinned references, never silently vendored.

For portability use `FDF_UNIVERSAL_INJECTION.md`. Record what actually ran, which host loaded which instructions and unknowns. Keep external human-review/protected-main gates HOLD until externally verified.
